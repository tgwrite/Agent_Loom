# Governance parity and mutation experiment

This reusable experiment compares Loom with an independently owned shared control.
Passing the same governance contracts is a prerequisite for comparing mutations.
It does not measure model quality, prove security isolation, or complete v0.1 acceptance.

The independent control lives in `control/`. It imports no Loom implementation.
The arms share native plugins, loading fixtures and domain adapters. Domain digest
verification remains a domain responsibility and is not counted as a Loom advantage.

## Shared contracts

Run `node test/governance-parity/run.mjs` after installing the existing optional
cross-application dependencies. This runs 50 cases per arm covering G1-G18, including
the actual shared pipeline initializer. The root `npm run check` runs 49 cases per
arm without those optional packages, using a synthetic SDK. These shared tests are
not evidence that native plugins ran.

`PARITY_ARM=loom|control` selects an arm and `PARITY_FILTER=G13` selects a guarantee
prefix. Set environment variables using the syntax appropriate to your shell.
All raw output is written under ignored `.test-tmp/governance-parity/`.

## Actual native applications

Use the pinned dependencies and real Pandoc described in
[`test/cross-application/README.md`](../cross-application/README.md).
Set `PANDOC_PATH` to the local executable, then run:

```text
npm run build
node test/governance-parity/native.mjs
```

The full matrix runs two arms, A/B/C, and seven scenarios: normal, native hook
failure, afterRun failure, invalid aspect publication, two aspect failures, domain
failure followed by successful aspects, and delayed governance settlement.
This is 42 Tasks and 84 business Sessions, using deterministic model decisions.
No plugins are installed globally. Main provider inputs are captured outside the
aspect failure boundary. An external process inspects the running Task while a
required terminal write is blocked, then releases the write.

Optional `PARITY_APP=a|b|c` and `PARITY_SCENARIO` select a diagnostic subset.
Subsets do not satisfy the full native parity gate.

## Freeze and mutation

Pass the generated shared summary and native result paths to:

```text
node test/governance-parity/freeze.mjs <shared-summary> <native-result>
node test/governance-parity/mutate.mjs
```

The freeze rejects incomplete parity. The campaign verifies source/test hashes,
copies the frozen sources into isolated ignored workspaces and applies one source
patch at a time. It never mutates the active production checkout. Shared native
dependency directories are linked for reading; installed plugins are not edited.

Each result distinguishes build rejection, frozen regression failure, runtime
containment, actual semantic violation and unclassified survivors. A failing test
does not automatically prove the absence of a remaining runtime guard. Manual
diagnosis must retain evidence and cannot retroactively claim automated detection.

M06 targets the real common domain initializer. M18 requires an actual separate
application migration path; no application-specific branch is invented to create
a mutant. Structurally inapplicable candidates remain in the ledger and are
excluded from matched detection denominators.

The legacy fixtures are static anonymous wire examples of the public pre-M1
observer format (`366d110`) and pre-M2 native Artifact format (`55c066e`). They
are not generated by stripping fields from the current writer at test time.
Their byte hashes are included in the campaign freeze.

The control supports the bounded experimental surface, not every Loom public API.
The storage fault model is a live process with a single writer and failing or
delayed file operations. There is no power-loss, multi-writer or recovery claim.
