# Native review publication protocol

The original `web.source@1` and `web.report@1` contracts and their verification
remain unchanged; see [the business Handoff](../lightweight/HANDOFF.md).

The new `conversation-review` aspect declares:

| Contract | Native file | Verification |
| --- | --- | --- |
| retro.session-review@1 | Per-session Markdown generated by the review plugin | COMPLETED |
| retro.improvement-report@1 | Timestamped native improvement Markdown | COMPLETED |

1. Loom starts an explicit Profile and supplies its bound Task/Session workspace.
2. After the domain run, the aspect adapter copies that Session's native JSONL
   without rewriting content into a new isolated Pi agent directory. The header
   must identify the current native workspace. Only this log is discoverable.
3. The adapter selects a fresh native output directory and invokes the registered
   `conversation-retro` command with one candidate and one worker. The command
   performs its own review and writes both native Markdown files.
4. Success requires command completion, the expected per-session file and source
   header, exactly one timestamped final report and agreement with its native latest
   alias. Existing output directories, missing or empty output fail. A later file
   appearance alone does not publish an artifact.
5. The adapter returns only contract, Task-relative path and native verification
   facts. The Host derives Plugin/Task/Session/Actor/Runtime, checks containment,
   hashes the bytes and registers the artifacts while the Session is running.
6. Failure is attributed to the aspect, with no fabricated successful review.
   The business Session can complete if its own execution succeeds. Storage failure
   remains fatal because a missing governance record cannot count as a verified run.

The mutable `workflow-improvement-report-latest.md` file is never the indexed
payload. No review contract is a required input to the business report Profile.
The two review files form this adapter's successful publication batch; a partial
native review is retained locally for diagnosis but is not marked COMPLETED.

Input projection, Pi configuration, native reports and diagnostics remain ignored.
The native command's UI status sink is observed for local diagnostics only; it does
not write model messages or substitute test-generated review content. Test model
responses exercise delivery and governance, not the correctness of retrospective advice.
